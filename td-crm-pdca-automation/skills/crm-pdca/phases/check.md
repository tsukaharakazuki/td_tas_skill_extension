# Phase 3: Check

目的: 配信結果を多角的に分析し、施策の良し悪しを判定する。

## ステップ全体像

```
[1] 基礎集計の確認・体制整備
      ↓
[2] 多角分析（配信/流入/行動/購買）
      ↓
[3] KPI達成度判定
      ↓
[4] 洞察サマリ作成
      ↓
[5] 振り返り会議（PM/施策/CR）
```

---

## ステップ1: 【分析】基礎集計の確認

### まず確認
`environment.yml` の `engage_analytics` を確認する。
- `available: true` → `engage_analytics.tables` を使って配信結果（開封・クリック・エラー等）を集計
- `available: false` → 下記を提案（外部配信ツールの場合は、そのツールの配信結果レポートを共有してもらう）

### 未整備の場合は提案
```
【分析】配信結果の基礎集計が未構築のようです。
以下パッケージの導入を推奨します（Engage Studio 利用時）:

<engage_analytics.package_url>

導入すれば配信ログから開封・クリック・エラー等が自動集計され、
以降の PDCA 全てで活用できます。

導入を進めますか？
```

→ **AskUserQuestion** で判断を仰ぐ。

## ステップ2: 【分析】多角分析

### A. 配信パフォーマンス
- 到達数、到達率
- 開封数、開封率（配信後7日時点 と 累計）
- CTR
- 不達・エラー内訳
- A/Bテスト群別の差分

### B. Web流入
`reference/data-sources.md` の「5-4. 配信経由のサイト流入」を使う（判定条件は `environment.yml` の `inflow_rule`）。
`tables.weblog.enabled: false` の場合、B・C は省略し、その旨をレポートに明記する。

### C. サイト内行動
- 流入後のPV・滞在
- 商品ページ到達率
- カート投入率
- 離脱ポイント

### D. 購買
- CV数、CVR
- 平均注文単価
- 新規 vs. 既存
- クロスセル（他ブランド・他カテゴリ購入）
- 配信期間後 `defaults.ltv_followup_days` 日のLTV増分（コントロール群との差分。`reference/data-sources.md` 5-5）

### E. セグメント詳細 & コントロール群比較
- 配信群 vs. コントロール群の差分
- セグメント内さらに細分化した分析（年代別、F数別等）

### 全ての分析は `reference/data-sources.md`（`related_skills.sql_guideline` が設定されていればそのSkillも）のクエリパターン準拠

## ステップ3: KPI達成度判定

`projects/<project-id>/01_plan/kpi.md` と突合:

```markdown
| KPI | 目標 | 実績 | 達成率 | 判定 |
|---|---|---|---|---|
| 配信後14日購買率 | 5.0% | 6.2% | 124% | ◎ |
| 配信経由売上 | ¥500万 | ¥430万 | 86% | △ |
| 開封率 | 25% | 32% | 128% | ◎ |
| CTR | 3% | 2.1% | 70% | ✗ |
```

判定基準（`defaults.kpi_judgement` で変更可。既定値は以下）:
- ◎: 達成率 110%以上
- ○: 90-110%
- △: 70-90%
- ✗: 70%未満

## ステップ4: 洞察サマリ作成

成果物: `projects/<project-id>/03_check/analysis_report.md` + `insights.md`

### insights.md テンプレート
```markdown
# 洞察サマリ — <project-id>

## 🎯 主要発見（3つ）
1. <発見1>（例: 開封は高いがCTRが低い → コピーは響いているがCTAが弱い可能性）
2. <発見2>
3. <発見3>

## 💡 想定外の発見
- <事前仮説と違った点>

## ⚠️ 要注意ポイント
- <コントロール群との差が小さい、など>

## 🔄 次サイクル仮説
- <修正したら伸びそうなポイント>
```

### ダッシュボード化が有効なケース
Checkレポートをクライアント向けに共有する場合、`related_skills.dashboard_mail`（既定 `html-dashboard-mail-workflow`）で HTML化+メール送付を提案。

## ステップ5: 振り返り（PM進行）

### 発言順序
1. **【分析】**: データの客観報告
2. **【施策】**: 実行面の振り返り（配信ミス・疲労・タイミング等）
3. **【CR】**: クリエイティブ面の振り返り（件名・コピー・CTA 等の読み解き）
4. **【PM】**: 全体総括と Action フェーズへの論点整理

### 振り返りで必ず聞く問い
- KPI達成/未達の最大要因は何か
- 想定と違った点は何か
- 続けるべき/やめるべき/変えるべきは何か

## Phase終了時の処理

- `project_state.json` を更新 → `current_phase: "action"`
- 分析レポート一式を Action フェーズに引き継ぎ

```

```
