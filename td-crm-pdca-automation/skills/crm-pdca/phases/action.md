# Phase 4: Action

目的: Check結果を受けて、次サイクルで何をするかをクライアントと一緒に決定する。

## ステップ全体像

```
[1] PMによる総括
      ↓
[2] 施策/CRによる修正案 or 継続案提示
      ↓
🙋承認④ 次サイクル意思決定
      ↓
[3] 次サイクル準備 or プロジェクト終了処理
```

---

## ステップ1: 【PM】総括

Check のインサイトを以下の構造で整理:

```markdown
# Action 総括 — <project-id>

## 施策評価サマリ
- 総合判定: <◎/○/△/✗>
- KPI達成状況: <ハイライト>

## 継続/修正/中止の論点
### 継続すべきこと
- <ワークした要素>

### 修正すべきこと
- <課題>: <修正方向性候補>

### 中止すべきこと（もしあれば）
- <効果なしだった要素>
```

---

## ステップ2: 【施策】&【CR】次アクション提案

### 判定パターン別の典型対応

#### 【継続パターン】総合◎・課題なし
```
【施策】現在の設計で継続配信を提案します。
  - 配信頻度: 隔週に拡大 or 月1維持
  - セグメント拡張: 類似層にリーチ拡大 (lookalike)

【CR】勝ちクリエイティブを横展開、A/B対象のみ入れ替え。
```

#### 【修正パターン】○～△・特定要素が未達
```
【施策】セグメント修正を提案:
  - 現状のセグメント内でCTRが低い層を除外
  - 高CVR層を特定し追加配信

【CR】CTA修正を提案:
  - 現状CTA「詳しくはこちら」→ 「30%OFFクーポンをもらう」に変更
  - 件名A/Bテスト再設計
```

#### 【中止パターン】✗・根本的に効果薄
```
【PM】今回の仮説は不成立の可能性。別アプローチへのピボットを提案。
  オプション:
    A. 全く別のターゲット層で再試行
    B. チャネルを変更（メール→LINE 等）
    C. 一時中止して市場・競合分析から再構築
```

## 🙋 承認④: 次サイクル意思決定

**AskUserQuestion** で以下を提示:

```
【PM】Check結果を踏まえた次サイクルの提案です。

意思決定が必要な点:
  1. <論点1> → 推奨: <A/B/C>
  2. <論点2> → 推奨: <A/B/C>

次サイクル全体の方向性:
  オプションA: 現状継続（セグメント拡大）
  オプションB: 修正継続（<具体的修正点>）
  オプションC: 中止・ピボット
  オプションD: プロジェクト完了（成果◎で学び確定）

→ どれで進めますか？
```

### 承認結果の記録
`projects/<project-id>/04_action/next_action.md`

```markdown
# 次アクション決定 — <project-id>

## 決定内容（<YYYY-MM-DD> 承認）
- 選択: オプション<X>
- 具体アクション:
  - <>
  - <>
- 次サイクル目標:

## 承認者
- クライアント: <>
- 承認日時: <>

## 判断理由（議事）
<議論の要点>
```

## ステップ3: 次サイクル準備 or プロジェクト終了

### 継続/修正の場合
- 新しいサイクルの `project_state.json` を更新
- `current_phase` を `plan` に戻す
- 次サイクル番号を増やす（`cycle: 2` 等）
- Plan フェーズに戻って再開（ただし初回ヒアリングは省略可能）

### プロジェクト終了の場合
- `project_state.json` → `status: "completed"`
- `projects/<project-id>/README.md` にプロジェクト総括を記載
  - 全サイクルの要点
  - 得られた学び（横展開可能な知見）
  - 他プロジェクトへの示唆

### 横展開提案
終了時、PMは「この学びを横展開できるプロジェクトはないか」を提案:
```
【PM】本プロジェクトで得た「<学び>」は、以下にも応用できそうです:
  - <他プロジェクト候補1>
  - <他プロジェクト候補2>

横展開プロジェクトを立ち上げますか？
```

---

## Phase終了時の処理

- `project_state.json` 更新（継続 or completed）
- 次サイクルがある場合: Plan から再開
- 全サイクル完了の場合: アーカイブ (`projects/_archive/` に移動を提案)

### 学習の蓄積
プロジェクト終了時、クロスプロジェクトで活かせる知見は
`projects/learnings.md` に追記（PMが実施）。

例:
```markdown
## 2026-10-06 休眠掘り起こしプロジェクトから
- 180日以上の休眠層にはクーポン訴求より「お久しぶり」感情訴求が刺さる
- LINE配信のCTR は メール の 2.3倍
```
