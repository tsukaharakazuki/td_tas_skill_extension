# 3モード共通版への移行

## 変更点

旧版のカート専用サンプルから、`mode: cart | browser | both` を選択する共通コアへ移行しています。配布フォルダ名とSkill名は維持していますが、**旧版の本番プロジェクトへそのまま上書きしないでください**。

旧版は `params.example.yml` が設計・ヒアリング用であり、Workflowが実際に参照する値は `.dig` / SQLに直接記載されていました。新しい版では実際に読み込まれる `config/params.yml` を設定の入口にします。旧版の `-p test_mode=...` による切替案内も、設定ファイルの編集へ変更します。

旧 `cart_abandonment_nightly.dig` と単独配信用 `send_email.dig` は、古いリストの再送や通常版との競合を防ぐため停止用の互換ファイルとします。夜間分も `cart_abandonment.dig` の設定（`window.kind: overnight`）で処理し、本番配信は共通パイプライン内でのみ行います。旧名を実行しても、そのままメール配信する動作にはなりません。

| 項目 | 3モード共通版 |
|---|---|
| 最初のヒアリング | カートのみ／ブラウザのみ／両方を明示的に選択 |
| 入力 | 元システム固有の列を、文書化した共通スキーマへ変換 |
| ブラウザ放棄 | 最新閲覧商品、人物単位の後続活動・カート・購入抑止 |
| 両方 | カート優先、共通履歴と合算キャップ |
| 通常／夜間分 | 設定した対象時間範囲を共通コアで処理 |
| 配布時の動作 | Workflow実行・配信は無効、安全ガードは有効、有効なスケジュールなし |
| 配信履歴 | 候補や予約を「配信成功」と扱わず、実配信結果を別途確認 |

## 安全な移行手順

1. 新しいプロジェクト名・別の出力プレフィックスで顧客用コピーを作る。既存の本番Workflowと履歴は変更しない。
2. 旧 `.dig` / SQLの直接指定値と、顧客が実際に採用した条件を棚卸しする。見本の設定値を本番仕様とみなさない。
3. Webログの時刻・識別子、宛先・最新同意、カート粒度、商品、注文、配信履歴を共通入力へ対応付ける。
4. カート用とブラウザ用のCampaign・Liquid変数を確認する。新しい基本出力と旧テンプレートのカラム名は自動的に互換ではない。顧客用の送信SQLで必要な別名・型を明示し、表示をテストする。
5. ポイント・セグメント・クーポン・レコメンド・在庫僅少分岐を使う場合、該当アダプターのキー・粒度・出力契約を確認する。旧版の推薦アルゴリズムやRFM分類を無条件に引き継がない。
6. 配信を無効のまま3モードの抽出結果・境界時刻・購入／同意除外・頻度キャップを比較する。稼働中プロジェクトと同じワークテーブルへ書かない。
7. 既存の配信履歴を共通履歴の形式へ移す。切替直後の再配信を避けるため、日付境界・人物ID・施策種別・予約状態を確認する。候補履歴だけしかない場合、その制約を明示する。
8. 承認済みテスト用Campaignと宛先で、dry-run→件数確認→承認→テスト送信を行う。
9. 本番切替の承認後、旧版を停止してから新版スケジュールを有効にする。同じ人物へ旧版と新版が同時に配信しないようにする。

## ブラウザ放棄で確認する追加仕様

ブラウザ用の参考WFからは商品閲覧・購入/カート除外・頻度制御・夜間分の考え方を取り入れていますが、次は顧客の判断を必要とするため固定値として配布しません。

- URL/パスから商品IDを取り出す方法、SKUと親品番、商品公開・在庫ルール。
- 過去ログインによるCookie→人物IDのステッチ、保持期間、共有端末の許容方針。複数人物へ解決できるCookieを安易に1人へ結び付けない。
- 滞在最長商品と最終閲覧商品の2枠表示、滞在時間の最低条件、旧コホート比較用の属性。共通基本版の最新商品表示とは区別する。必要ならイベント粒度の滞在計算と追加出力を実装する。
- 顧客固有のRFM分類、レコメンド手法、地域抑止、未知住所の扱い、ポイント/クーポン。
- 他チャネルのWorkflow連鎖。メール施策を設定しただけで他システムへ送信しない。

「セッション終了から20分」と「セッションタイムアウト30分」のような不整合は、そのまま既定値へ移しません。最後の活動・無操作時間・入力遅延を踏まえた基準を使います。古い閲覧が条件を満たしていても、後続の活動・カート・購入を無視して配信しないようにします。

## 旧SQLの扱いと検証の限界

旧カートサンプルの高度なSQLは、比較・移植のために `cart-abandonment/reference/` 配下へ非実行形式で保存します。現行コアの入力・出力契約へ対応付ける前にそのまま実行しないでください。

同梱のローカルテストはSQLの条件・入力契約・Workflow構造を検証するものです。実TDのTrino/Digdag、接続先Campaign、実データの品質は別途検証が必要です。副作用を伴う実行は必ずdry-runと明示的な承認を経て行います。
